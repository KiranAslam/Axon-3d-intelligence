Large Language Models: From Text to the Next Token

A large language model turns a text sequence into numerical representations, processes its context through transformer layers, then estimates which token could come next. Repeating that step is how it generates text.

Architecture overview

Four stages from prompt to prediction

This is a simplified map of an inference pass. Real implementations differ in their layer design and decoding choices.

Split the prompt

A tokenizer maps pieces of text to vocabulary IDs.

01 · Input

Tokenization: dividing text into units

Before a language model can process a prompt, its text must be represented using the model's vocabulary.

1

From words to token IDs

A tokenizer breaks a sentence into tokens and assigns each token a vocabulary index. Depending on the tokenizer, a token may correspond to a complete word, part of a word, punctuation, or another text fragment.

Common words may fit in one token, while less familiar words can be represented by several smaller pieces. The ID is just an index—it does not, by itself, encode a human-readable definition.

02 · Representation

Embeddings: turning IDs into vectors

Neural-network operations work with numbers, so each token ID is mapped to a learned vector.

2

Learned token representations

An embedding matrix supplies a vector for each vocabulary entry. The model uses these values as its initial numerical representation of the input tokens.

Position information helps distinguish order: the same words arranged differently can communicate different things. Contextual processing in later layers further changes the representations.

03 · Context

Self-attention: sharing information across tokens

Attention lets a position draw on relevant information from other positions in the sequence.

3

Queries, keys, and values

For attention, the model derives query, key, and value vectors from token representations. Similarity between queries and keys produces scores that are normalized into weights.

Those weights control how information from the value vectors is combined. Multiple attention heads can learn different patterns of relationships between positions.

Keep in mind

Attention is a mathematical mechanism for mixing contextual information. It should not be mistaken for human understanding.

04 · Transformer block

Residual connections and normalization

Transformer layers use supporting operations around attention and feed-forward computations.

4

Helping information flow through layers

A residual connection adds a block's input to its computed output, giving information a path through the network. Normalization rescales activations to support stable processing.

The order and details of these operations depend on the model architecture; there is no single layout shared by every transformer.

05 · Feed-forward computation

The MLP transforms each position

Attention mixes context between sequence positions; the feed-forward network applies learned transformations at each position.

5

Learned transformations inside each layer

The multilayer perceptron (MLP), also called a feed-forward network, applies learned weights and nonlinear functions to token representations.

Attention and MLP computations are arranged in transformer blocks and repeated across the model's layers, progressively processing the sequence.

06 · Vocabulary scores

Final normalization and unembedding

After the transformer layers, the model turns its final representation into a score for each vocabulary token.

6

From hidden representation to logits

A final normalization is commonly applied before an output projection, sometimes called the unembedding matrix. This projection produces one logit per candidate vocabulary token.

Logits are raw scores, not probabilities. A larger score alone is not a guarantee that the corresponding token will be selected.

07 · Generation

Softmax and next-token selection

The model converts its scores into a distribution, then a decoding rule picks what to append next.

7

Predict, append, and repeat

Softmax maps the vocabulary logits to a probability distribution. A decoding strategy then selects a token—for example, by choosing the highest-probability option or sampling among alternatives.

The chosen token is appended to the sequence, and the model runs another prediction using the expanded context. This repeated next-token process is known as autoregressive generation.

What to follow in the walkthrough

These steps connect the main pieces of the inference pipeline.

  • Trace a token from its vocabulary ID to its embedding vector.
  • Follow how attention combines information from different sequence positions.
  • Compare context-mixing in attention with per-position processing in the MLP.
  • See how vocabulary logits become probabilities for the next token.
  • Notice how each generated token becomes part of the context for the next prediction.
Important context

A simplified view of inference

This page describes a simplified information flow during LLM inference. Real systems vary in their number of layers, dimensions, architectural details, and decoding settings. The walkthrough is intended to explain the broad stages—not to show a specific production model, its training process, or every computation it performs.
