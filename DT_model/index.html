Decision Trees: From Clinical Features to a Classification

This model follows a sequence of feature-based splits to classify whether a patient has heart disease. Trace the branches from the root to a leaf to see how the tree reaches a yes-or-no output.

How the tree works

Four steps from patient data to a leaf

Each decision uses one of the selected clinical features. The route through the branches ends at a classification.

01 · INPUTPatient record

Read the features

The model receives the four clinical feature values for a patient.

02 · SPLITDecision node

Test a condition

A feature value is compared with a learned split rule at a decision node.

03 · PATHBranch traversal

Follow the branch

The result of each test determines which branch the record follows next.

04 · OUTPUTLeaf node

Return a class

The final leaf provides the model's heart-disease classification.

01 · Model structure

A compact tree with readable paths

The trained classifier contains 15 nodes across four levels, ending in eight leaves.

Decision nodes

Four clinical features

The tree uses chest pain type, major vessels colored, thalassemia test, and ST segment slope to divide examples into smaller groups.

Leaf nodes

Yes-or-no classification

Each leaf represents the class assigned after following a path through the tree. A prediction follows the conditions from the root until it reaches one of these leaves.

02 · Dataset

Cleveland heart disease data

The supplied dataset contains 296 patient records, separated into training and testing examples.

296Patients in dataset
236Training examples
60Test examples
Feature 01

Chest pain type

A categorical feature describing the recorded chest-pain type.

Feature 02

Major vessels colored

The recorded number of major vessels colored by fluoroscopy.

Feature 03

Thalassemia test

The categorical thalassemia test result included in the model input.

Feature 04

ST segment slope

The recorded slope of the ST segment during exercise testing.
